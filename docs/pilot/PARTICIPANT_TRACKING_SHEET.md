## 1. Operating Instructions for Coordinators

The **Participant Tracking Sheet** is the central operational record used by the UrsBiz pilot team to manage participant progression through each milestone of the 4-week pilot.

### Important Data Integrity Rules:
- **No Fabricated Records**: Do not enter fictional names, dummy companies, or simulated feedback. Rows must remain labeled `[Pending Selection]` until an actual business is recruited and has signed the consent form.
- **Data Minimization**: Store only operational tracking details in this sheet. Never paste proprietary customer transaction rows, bank details, or passwords here.
- **Status Lifecycle**: Track each business through:
  `Invited` $\rightarrow$ `Consent Signed` $\rightarrow$ `Onboarded` $\rightarrow$ `Data Ingested` $\rightarrow$ `Week 1 Active` $\rightarrow$ `Week 2 Active` $\rightarrow$ `Week 3 Active` $\rightarrow$ `Completed` (or `Withdrawn`).

## 2. Participant Tracking Schema

| Column Identifier | Description & Validation Rules |
| :--- | :--- |
| `participant_id` | Unique pilot code assigned to the participant (e.g. `MSME-PILOT-001` through `005`). |
| `business_legal_name` | Registered legal entity name (filled only after consent form signature). |
| `contact_person` | Full name of the primary decision-maker participating in the pilot. |
| `designation` | Role of contact person (Proprietor, Managing Partner, Director, General Manager). |
| `sector_industry` | Primary industry (e.g. Food Processing, Apparel, Retail Kirana, Light Engineering). |
| `enterprise_tier` | Official MSME classification: `Micro` ($\le$ ₹5 Cr), `Small` (₹5–50 Cr), or `Medium` (₹50–250 Cr). |
| `consent_signed_date` | Date the signed consent form was received and countersigned (`YYYY-MM-DD`). |
| `account_created` | `Yes` / `No` indicating whether the user registered on the platform. |
| `profile_completed` | `Yes` / `No` indicating whether the 3-step business profile setup is complete. |
| `baseline_health_score`| Initial Business Health Score ($0-100$) generated by UrsBiz upon profile setup. |
| `data_upload_date` | Date of first successful sales dataset upload (`YYYY-MM-DD`). |
| `rows_ingested` | Number of valid transaction rows accepted by the ingestion engine. |
| `data_quality_score` | Automated quality rating ($0-100\%$) assigned by UrsBiz during file ingestion. |
| `week1_checkin_date` | Date the Week 1 check-in survey or call was completed (`YYYY-MM-DD`). |
| `week2_checkin_date` | Date the Week 2 check-in survey or call was completed (`YYYY-MM-DD`). |
| `week3_checkin_date` | Date the Week 3 check-in survey or call was completed (`YYYY-MM-DD`). |
| `completion_survey_date`| Date the final exit interview and questionnaire were completed (`YYYY-MM-DD`). |
| `exit_status` | Final pilot standing: `Active`, `Completed`, or `Withdrawn`. |
| `coordinator_assigned` | Full name of the designated UrsBiz engineering coordinator. |
| `notes_issues` | Log of any open bugs, support requests, or specific operational observations. |

## 4. Participant Milestone Checklist

### Step 1: Pre-Pilot Enrollment
- [ ] Deliver Pilot Invitation (`01_PILOT_INVITATION.md`).
- [ ] Conduct 15-minute qualification conversation.
- [ ] Collect signed Participant Informed Consent Form (`02_PARTICIPANT_CONSENT_FORM.md`).
- [ ] Populate participant metadata in tracking spreadsheet.

### Step 2: Onboarding & Setup
- [ ] Execute Business Onboarding Checklist (`03_BUSINESS_ONBOARDING_CHECKLIST.md`).
- [ ] Assist with user account creation and profile wizard completion.
- [ ] Record baseline Business Health Score in tracking table.

### Step 3: Sales Data Ingestion
- [ ] Provide Data Collection Checklist (`04_DATA_COLLECTION_CHECKLIST.md`) and template (`sales_upload_template.csv`).
- [ ] Review uploaded file and verify automated Data Quality Score ($> 85\%$ target).
- [ ] Record upload date and ingested row count.

### Step 4: Weekly Engagement & Feedback
- [ ] Administer Week 1 Feedback Survey (`09_WEEKLY_FEEDBACK_QUESTIONNAIRE.md`).
- [ ] Administer Week 2 Feedback Survey.
- [ ] Administer Week 3 Feedback Survey.
- [ ] Log any reported bugs or UI hurdles via Issue Form (`08_ISSUE_REPORTING_FORM.md`).

### Step 5: Pilot Wrap-Up & Evaluation
- [ ] Conduct 20-minute exit interview using Completion Questionnaire (`10_PILOT_COMPLETION_QUESTIONNAIRE.md`).
- [ ] Offer full data export and verify if participant wishes to retain or delete data.
- [ ] Compile aggregated, anonymized feasibility findings.
